# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

Phase 1b: engine core and movement sandbox built, feel signed off (2026-10-19). Mission 1 (`mesto`) is playable at `game.html`: walk, pick items, use every object, reach the level end. For a browser clone of Colony 28 (1996/97 Czech DOS cinematic side-scroller).

- `docs/requirements.md` - decision log and open questions. Source of truth for what is decided. Design spec: `docs/superpowers/specs/2026-10-17-colony2080-design.md` (phases, movement set). Phase 1b plan: `docs/superpowers/plans/2026-10-17-engine-core-movement-sandbox.md` (built).
- `WORK-REPORT.md` - local session handoff (gitignored): open follow-ups and abandoned approaches.
- `docs/research/README.md` - research summary (mechanics, level 1 task graph, data formats, open gaps). Read before answering questions about the original game.
- `config/` - draft JSON configs (`"status": "draft"`). Each cites its research or decision `source`.
- `spikes/` - throwaway prototypes.

## Commands

- `npm run dev` - Vite dev server, opens the home page (`index.html`: game name, mission select, dev links to the sandbox and every spike page) in browser. Agents start bare `npx vite --port 5199 --strictPort` (no browser); never pass `--open false`, Vite reads `false` as path `/false`.
- `npm run build` - production build of `index.html`, `sandbox.html` and `game.html` into `dist/`; `scripts/production.ts` (plugin in `vite.config.ts`) keeps the original game out of the published site: config JSON loses its citation and Czech-name text (`source`, `note`, `units`, `description`, `csName`, `cs`, `preview` blanked, `refs` emptied), `spikes/` is copied as a production variant (`<!-- originals -->` blocks cut, `shared/originals.js` switched off), and the build fails if any file in `dist/` still names the original game (`ORIGINAL_GAME` patterns). Code names (`xbot`, `C28_CONFIG`, `mesto`) may stay.
- `npm run preview` - production build, then serves `dist/` and opens the home page: the website as published (production spike variants without original game resources). Rerun after changes; it does not watch. Agents run `npx vite build && npx vite preview --port 5198 --strictPort`.
- `npm test` - Vitest (node environment) over `src/**/*.test.ts`.
- `npm run lint` - ESLint; `src/engine/**` may not import React, Zustand, `game/` or `sandbox/`.
- `npm run typecheck` - `tsc --noEmit`.
- `npm run test:visual` - Playwright runs `tools/visual/compare.html`: spike vs port robot trees and renders, hero and `enemy` variant, plus each env asset the sandbox uses (states, game LOD, ladder and sized variants) against its spike. The own-matrix render may differ by a few edge pixels because Chromium stores scale/translate DOMMatrix values as float32.

## Stack and architecture

Decided in `docs/requirements.md`:

- TypeScript + Vite. React only for the UI shell. Zustand bridges engine state to UI.
- Custom engine in plain TypeScript on Canvas 2D. Engine must not depend on React. No Next.js, no three.js, no DOS emulator.
- Art is vector, drawn as code. Not pixel art, not original assets. View scales to device (no fixed 320x200 canvas).
- Cutscenes (item use, story) are in-engine animated vector scenes, not video files.
- Level logic is a task dependency web: each task has `requires` / `consumes` / `gives` over `item:*`, `flag:*`, `weapon:*` tokens (see `config/levels/mesto/tasks.json`). Items live in `config/items.json` (`src/game/items.ts`); item props name their item and `world.inventory` holds picked ones.

Code layout:

- `src/engine/` - game-agnostic core: fixed-step loop, input (bindings, buffer, record / replay), tiles and collision, projectiles, view fit, rig tree, pose and draw. No React, Zustand, `game/` or `sandbox/` imports.
- `src/game/` - Colony 28 specifics: hero state machine (`hero/`), clip and movement config loaders, robot and gun models, sandbox level, scene and debug overlay renderers. `env/` ports the spike env primitives and assets to TypeScript (`paint.ts` primitives, `assets.ts` registry by id, `props.ts`, `machines.ts`, `structures.ts`, `buildings.ts`); the spikes stay the design source, so change an asset there first and re-port. `hero/look.ts` turns hero state into a pose: walk and run (and the blend into walking and running jumps) come from `hero/gait.ts`, a port of the spike gait engine checked against `gait.fixture.json` (regenerate from `spikes/movement/moves.js` in a browser when the spike gait changes); clips with `gait` in `config/hero/clips.json` have no pose keys. Every jump blends from its gait or its `base` pose into one leap pose in `blend`. Death clips keep the lowest body point on the floor, carry the gun until their `dropped` gun key, then let go and slide it back; a `dust` event starts the landing dust. Up while airborne (fall or jump) with the feet in a ladder column grabs the ladder, from any fall height and without fall damage. Ladder pose locks hands and feet on rungs from `hero.climb` (cells above the ladder bottom); the `ladder` env asset draws the rungs. No shadow while airborne. A hidden hero (`hero.hidden`) is drawn before the enemies so they walk in front of it (`heroBehindEnemies`). `shots.ts` turns `shot` events into hero bullets from the pose muzzle and stops them at walls with impact sparks; props block neither the hero nor bullets. Each hero `shot` event spends one `hero.ammo` (start `ammo` in `config/hero/movement.json`, kept on respawn); at 0 the hero stops firing and cannot draw the gun. `hero.blaster` is the E-Blaster ammo (null until picked up, kept on respawn, `blaster` in `config/hero/movement.json`); key 3 arms it and `fireBeam` in `shots.ts` turns its `beam` events into `world.beam`, drawn by `render/scene.ts`; each tick hits every enemy whose body box the beam line crosses between the hero body and the beam end, like bullets, and an enemy that leaves the beam gets the hit reaction again when it comes back. An empty E-Blaster switches to the gun, an empty gun to the E-Blaster, both empty to fists. Only the held weapon is drawn. The sandbox `weapon` prop (`config/levels/sandbox.json`) is picked like an item, gives the E-Blaster and is drawn (`eBlaster` env asset) and pickable only while `hero.blaster` is null (`onGround` in `level/sandboxLevel.ts`). While hidden, arrows set `facing` without leaving cover; `hero/look.ts` turns the front-view `head` and `face` joints toward it. Shoot held on hide release starts the attack with the held weapon (gun or E-Blaster fire at once, fists punch). Weapon keys swap the weapon at once in any live state (`quickSwitch` in `hero/hero.ts`); only while hidden does the front-view `weaponSwitch` clip play, cut short by any other input. Run mode starts on and survives respawn. While a lift moves the hero cannot jump or hide, and `keepOnDeck` stops it at the deck edge. `damage` in `hero/hero.ts` takes `energy.hit` off energy; at 0 it spends a shield and refills to `energy.max`, or kills the hero when none is left (`config/hero/movement.json`). `level/enemy.ts` is the sandbox enemy: a `Hero` body that patrols its platform, stops and shoots a hero it sees (walls and covered fog cells block its sight), takes hero bullets and punches (turning to the hero `reactMs` after the first hit) (`landPunches` in `shots.ts`, `punch` in `config/hero/movement.json`), fires bursts (`burst`, then stands `pauseMs`, `config/levels/sandbox.json`) with bullets that start at its body so a hero closer than its muzzle still gets hit, explodes, leaves scrap and respawns. It is drawn with its own rigs (`createRigs(lod, true)`, the robot `enemy` variant) and `ENEMY_PALETTE` (greyscale, red visor) in `render/scene.ts`. `render/environment.ts` draws the whole sandbox from env assets at game LOD: sky, backdrop scenery under a depth haze (`HAZE`), tiles, lifts, ladders and props; the static layers (below and above the hero) are cached per world and size in 512 device-px tiles (`render/tiles.ts`): tiles in the game window paint at once, the one-tile margin ring nearest first, at most one per layer per frame and none on a frame that painted a visible tile, all others drop; each tile paints only the assets within one cell of it. Every item in `config/items.json` names an env asset (the loader rejects one without), drawn on the ground and as its HUD icon. Shared rect type: `src/game/geometry.ts`. `level/terrain.ts` classifies solid tiles into wall fills, `ledges` (touch a wall or solid tiles) and free-standing `girders`. `config/levels/sandbox.json` holds the 48 x 32 map: `lifts` (each with optional `start` stop; `liftAt` picks the one the hero stands on or whose shaft it is in; `reach.test.ts` checks that a lift's two stop floors connect only through it), `enemies` (`respawnMs: null` means no respawn), and `backdrop` / `dressing` scenery (tall non-blocking scenery stays in the backdrop). `resetWorld` restores lifts, props, enemies, bullets and fog when the hero dies. `fog.ts` is fog of war: cells the hero's sight (1.5x the original playfield, `config/camera.json`, `sightCells` each side from `config/hero/movement.json`; walls and floors block it) ever covered stay uncovered; every bullet vanishes without a spark `sightCells` from its shooter (`endX`); `shots.ts` drops bullets at the first covered cell without a spark, `render/fog.ts` draws covered cells and the revealed-cells clip that hides the enemy, its bullets and sparks in fog. The hit effect is pose data: joint pose `tint` flashes the `chest` and `head` subtrees, plus a head snap and a star drawn by `render/scene.ts`.
- `src/game/hud/` - HUD frame: `layout.ts` (frame size in HUD units from the screen: at least 320 x 200, wider on wide screens, taller on narrow ones so the frame always fills the screen; game window rect, top bar plates (weapons, badge, run, inventory) and rod gaps; the badge plate takes the leftover width), `svg.ts` (frame as an SVG string from `HudState`; a held item icon replaces the hand, with its name label and an ENTER key tab), `icons.ts` (gun, fist and item icons drawn to canvas data URLs; item icons and names come from `config/items.json`). The sandbox passes `world.inventory.shown` to the HUD, and `hudState` in `src/sandbox/ui/Hud.tsx` shows slot 3 once `hero.blaster` is not null. The frame window is open; the game canvas shows through it.
- `src/home/` - `index.html` entry: fonts only; the page is static HTML.
- `src/game/run.ts` - shared runner: `startRun({ world, ui, afterStep, drawOver })` owns the loop, input, hero, enemies, fog, HUD and cache; the sandbox and the game page both call it.
- `src/game/level/mesto.ts` - `loadMesto` builds the mission 1 world through `loadSandbox` from `config/levels/mesto/` (`mestoJson`); `droidsOf` turns the 27 `chromeDroid` entries of `enemies.json` into non-respawning enemies with the sandbox enemy tuning. No flyers, guards or E-Blaster.
- `config/levels/mesto/map.json` - generated by `docs/research/tools/mestomap.py`, never hand-edit. Rows use `#` (solid wall or plank), `|` (invisible blocker, `TileGrid.solid` but not `wall`, so nothing is drawn) and `.`. `lifts` have N `stops`, optional `enabledBy` (flag that powers the lift) and `hint` (subtitle while it is off). `taskWalls` are walls a task removes, not in `rows`. `SHAFT_FLOORS` in the script are `|` blockers under the two bottom stops that stop a survivable drop past a lift.
- `config/levels/mesto/world.json` - scenery and props. Prop `kind`: `item` (pick up), `object` (use), `gate` (no use, opened by `sets`; `solidStates` and `cells` make it block while in those states). `shootable` (`hits`, `state`, `gives`, `subtitle`) makes a prop take hero bullets and beams (`shots.ts`); `art` (cells) moves the art off the use x.
- `src/game/level/tasks.ts` - `runUse` runs the first open task of the used object whose `requires` hold: the shown item is the newest one picked (stack, only the top is usable), every `consumes` item use pops it, `gives` adds items or flags, `sets` moves other props to a state, then `applyBlocks` rebuilds the prop blockers and the task subtitle shows. Each task runs once. A use with no match says a hint. `flag:levelComplete` ends the level.
- `src/game/level/reach.ts` - reach graph of the map (walk, jump, ladder, lift) used by tests (`route.test.ts`, `reach.test.ts`) to check that tasks are reachable in order and lifts are not bypassed.
- `src/play/` - `game.html` entry: `main.tsx` calls `startRun` with `loadMesto`, fog on, the sandbox HUD, `Subtitle.tsx` (yellow caption at the bottom of the game window) and `LevelEnd.tsx` (level complete caption with a link home). `originalOverlay.ts` loads only in dev (`import.meta.env.DEV`): key `o` toggles the original map over the level and `window.__teleport`, `__overlay`, `__fog`, `__pause` are test helpers.
- Rendering: `visibleEnemies` (`render/scene.ts`) skips pose and draw of enemies outside the view plus a margin; the static cache indexes terrain runs, ladders and scenery per cache tile (`bucketByTile`). New env assets for mission 1 include `tunnelGate`.
- `src/sandbox/` - `sandbox.html` entry: `main.tsx` runs the loop, `store.ts` (Zustand) holds UI state and live tuning, `main.tsx` frames the game with `followView` (`src/engine/render/view.ts`): the hero stays in the view centre of `view` cells from `config/camera.json`, clamped at the map edges, and fog, overlays and the environment cache use the same transform. `ui/Hud.tsx` overlays the HUD frame (`dangerouslySetInnerHTML` of `hudSvg`, rebuilt only when life, reserve, shields, ammo, blaster ammo, weapon, run mode, shown item or size change) and `main.tsx` clips and fits the game to its window, `ui/` holds the React debug panel (time controls, overlays, record / replay, hero buttons, live ammo, blaster ammo (above 0 gives the E-Blaster) and shields (inputs clamped to their range), tuning with JSON export for `config/hero/`). The engine pushes into the store once per rendered frame and reads tuning from it each step.

Build order: movement overview page, engine core and movement sandbox, cutscene framework, Colony 28 clone systems, then mission 1 (`mesto`).

## Spikes

Throwaway prototypes. They read `config/` through generated `spikes/shared/config.js` (`window.C28_CONFIG`); after editing `config/robots/*.json`, `config/cutscenes/*.json` or `config/levels/mesto/objects.json` run `node spikes/shared/build-config.mjs`. Every reference to the original game (images, file names, labels) goes through `spikes/shared/originals.js` (`ORIGINALS.on`, `src(path)`, `previewSheet`, `cutscenes`) or sits in an `<!-- originals -->` block; visible page text never names it, so the production build can drop it. No server needed: open in a browser via `file://` or with the VS Code "Live Preview" extension (`ms-vscode.live-server`). Plain HTML previews in VS Code webviews block the relative script and image loads.

- `spikes/shared/xbot.js` - hero robot model (front, side, back) as a Canvas 2D part tree with named rig joints (`hip*`, `knee*`, `ankle*`, `arm*`, `fore*`, `body`, `head` and `chest` (side view), `head` and `face` (front view); back legs `leg*`, `thigh*`, `shin*`) and hand, back (side and back view) and foot (`heel*`, `toe*`; back view `foot*`) hooks. `L` / `R` suffixes name the screen side, not the robot's side: front `armL` is the robot's right arm, back `armL` its left. A pose value is an angle or `{ rot, dx, dy, sx, sy, tint }` (`tint` shades that joint's subtree, e.g. `{ brightness, saturate }`). Hand hooks render before the hand parts, so a held prop sits inside the grip. `locate(root, hook, pose)` returns a hook's matrix; `solve(...)` fits two arm joints to a target. Builder options: `lod` (game LOD, use with `render(..., { simple: true })`), `farLimbs`, `badge` (side), `propBehindArm` (side, front), `rightArmFirst` (front), `leftArmBehind`, `rightForeBehind`, `thumbsBehind`, `forearmsUnder` (back), `enemy` (all views: no antennas, head crest, trefoil badge, horizontal leg stripes, shin slots or back panel lines; knees in leg armour). Classic script exposing `window.XBOT`, not an ES module, so pages work from `file://`.
- `spikes/shared/gun.js` - rotary gun model (`GUN.draw`, `GUN.hook` for hand and `back` hooks, `GUN.slung` draws it at the rest-pose back hook) and `GUN.holdPoses(side, front)` carry poses plus `FRONT_BARREL` (pass as `barrel` to `draw` / `hook`). Barrel keeps its true length unless the robot silhouette covers the muzzle in a view; then it stretches until the muzzle clears the silhouette by one barrel thickness. Needs `xbot.js` first.
- `spikes/robot-design/index.html` - design sheet rendering `xbot.js`, with palette editor, level guides, a game-size row of the simplified robot and original reference frames.
- `spikes/gun-design/index.html` - gun design sheet: side, held side and front, slung back, game size, original references.
- `spikes/enemy-design/index.html` - enemy design sheet: hero rig built with `enemy: true`, recoloured by `XBOT.shade` keeping the red visor (brightness, saturation sliders, per-colour overrides, JSON export), full and game size, face-off with the hero, original references.
- `spikes/shared/env.js` - environment asset registry and Canvas 2D primitives (`window.ENV`: `define`, `draw`, `PALETTE` with 4-tone materials (`olive`, `denim`, `jacket`, `skin`, `hair`, `boot` among them), `P.box` / `poly` / `cylV` / `mesh` / `truss` / `hazard` (colour options) / `slab` (thin-edge fill for big surfaces) / `shape` / `line` / `curve` / `beam` ...). Units are original pixels (1 tile = 24, floor at y 0, up is negative). An asset is `{ id, box, anim, draw(ctx, state, t) }`; `state` indexes the object's `states` in `config/levels/mesto/objects.json`. `size` option on `ENV.draw` (`w`, `h`, `top`, `py`, `rung`) draws an asset at another width or height, defaults keep the sheet output; `ladder` is a non-interactive structure asset (`rung` spacing matches `RUNG`). Assets live in `env-props.js`, `env-machines.js`, `env-structures.js`, `env-buildings.js` (the object's `sheet`).
- `spikes/env-design/index.html` - level 1 environment sheet: every object from `config/levels/mesto/objects.json` (interactive first), our vector variant per state, original crops under it, hero for scale, game LOD and tile grid toggles.
- `spikes/items-design/index.html` - item sheet: each `config/items.json` item with its original inventory preview spinning (cropped from `docs/research/gamedata/png/PR*_sheet.png`, local only), our env asset, HUD icon, game LOD and other states.
- `spikes/hud-design/index.html` - HUD frame design sheet (inline SVG built from strings): aspect, weapon, bonus, ammo, life, run, shields and item controls, side by side with original screenshots. Gun and fist icons render from `gun.js` and `xbot.js` to canvas images. Same layout as `src/game/hud/`; change both together.
- `spikes/movement/movement.html`, `interaction.html`, `fight.html` - movement overview by category, sharing `moves.js` and `style.css`: one non-interactive cell per move looping forever (cutscene cells add a progress bar and loop time), game-LOD robot, Fists / Gun / Blaster switch at the top (Blaster: the hero holds the E-Blaster and the shooting cells fire its beam). An interaction can trigger a cutscene (`triggering` in `moves.js`): the cell plays the interaction in front of the cutscene backdrop (`backdrop(ctx, x, floorY, scale, t)`, same world at robot scale), then the cutscene. Click such a cell to open the cutscene player (`player.js`, `interaction.html` only): scrubber, speed, loop, side-by-side original frames, palette editor with JSON export.
- `spikes/shared/cutscenes.js` - vector cutscenes (`window.CUTSCENES`), each `{ name, duration, palette, backdrop, render(ctx, w, h, t), ref }`. `crowbarDoor` (crowbar opens train door, agreed version) uses `xbot.js` with a two-handed grip. Tracks, clip window (`clip.start..clip.end` on the original `METROPAC.ANM` timeline), robot x (same in both shots), crowbar size (same in both views) and pry swing (`pullArmDeg` / `pullForeDeg`) come from `config/cutscenes/crowbar-door.json`; stance is the `moves.js` `STAND` pose; `ref` maps time to original `METROPAC.ANM` frames in `docs/research/gamedata/png/METROPAC/`. Played by the `Use crowbar` cell in `spikes/movement/interaction.html`.

## Research tools

`docs/research/tools/*.py` - Python decoders for original game data (numpy, Pillow). Positional CLI args, no `--help`.

- `fli.py` - Autodesk FLI decoder (all `.GRA` / `.ANM` files are FLI).
- `dumpframes.py <file.anm|gra> <outdir>` - dump frames as PNG + `.npy` plus `pal.npy`.
- `rendermap.py <Mxy.MAP> <frames dir> <out.png> [width] [scale] [frame offset] [index base]` - render a 160x80 map from dumped tileset frames.
- `tiles.py`, `stream.py`, `rewidth.py`, `width.py`, `localwidth.py` - inspect raw frame data at guessed widths.
- `pstrings.py <exe> [minlen]` - dump Pascal strings (cp852) from executables.

Binary and media research folders are local only (copyrighted, large); the list lives in `.gitignore`. A fresh clone lacks them, so spike reference panels stay empty. Original game files live in `docs/research/gamedata/raw/C28/`. `docs/research/video/` holds gameplay footage and picked reference frames (`frames-best/`, named by timestamp and content).
