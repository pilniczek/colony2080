## Reporting work

Every final report that adds, changes or finds something visible in a mission map gives one `moveto(x,y)` per spot (world.json coords, y the floor row), on a cell the hero can stand on next to the spot, so the user can check it in game. More than 3 spots: also give every `moveto` on one line, separated by spaces, ready to paste into the debug panel Tour box. Changes with no map spot (films, HUD, code only) say how to see them instead (e.g. debug panel Films).

## Commands

- `npm run dev` - Vite dev server, opens the home page (`index.html`: game name, mission select, dev links to the sandbox and every spike page) in browser. Agents start bare `npx vite --port 5199 --strictPort` (no browser); never pass `--open false`, Vite reads `false` as path `/false`.
- `npm run build` - production build of `index.html`, `sandbox.html` and `game.html` into `dist/` (`cheats.html` is dev only); `scripts/production.ts` (plugin in `vite.config.ts`) keeps the original game out of the published site: config JSON (page and Worker bundles, `scrub` plugin and `worker.plugins`) loses its citation and Czech-name text (`source`, `note`, `units`, `description`, `csName`, `cs`, `preview` blanked, except `cs` in `config/items.json`, the Czech item names the game shows (`scrubConfigFile`), `refs` emptied), `spikes/` is copied as a production variant (`<!-- originals -->` blocks cut, `shared/originals.js` switched off), `index.html` loses its `data-dev` elements (missions 2-4, the cheats link), and the build fails if any file in `dist/` still names the original game (`ORIGINAL_GAME` patterns). Code names (`xbot`, `C28_CONFIG`, `mesto`) may stay.
- `npm run preview` - production build, then serves `dist/` and opens the home page: the website as published (production spike variants without original game resources). Rerun after changes; it does not watch. Agents run `npx vite build && npx vite preview --port 5198 --strictPort`.
- `npm run dev:debug` / `npm run preview:debug` - same with Vite mode `debugging`: `.env.debugging` sets `VITE_START_CHEAT=c2080isdebugging`, which `startRun` enters at start (any cheat code works there).
- `npm test` - Vitest (node environment) over `src/**/*.test.ts`.
- `npm run lint` - ESLint; `src/engine/**` may not import React, Zustand, `game/` or `sandbox/`.
- `npm run typecheck` - `tsc --noEmit`.
- `npm run test:visual` - Playwright runs `tools/visual/compare.html`: spike vs port robot trees and renders, hero and `enemy` variant, plus each env asset the sandbox uses (states, game LOD, ladder and sized variants) against its spike, and every cutscene at 9 times and 2 sizes, bare and filmed. `VISUAL_ONLY=id1,id2` runs only those cutscenes. The own-matrix render may differ by a few edge pixels because Chromium stores scale/translate DOMMatrix values as float32.
- `npm run sound:compare [id ...]` - renders each sound recipe and scores it against its original sound (sample ratio, envelope correlation, spectrogram distance, level); `tools/sound/compare.ts` holds `ORIGINAL_OF`, the id to original file map, and writes spectrogram PNG pairs to the OS temp dir (`c2080-sound/sound`). Needs the local research files.

## Stack and architecture

Decided in `docs/requirements.md`:

- TypeScript + Vite. React only for the UI shell. Zustand bridges engine state to UI.
- Custom engine in plain TypeScript on Canvas 2D. Engine must not depend on React. No Next.js, no three.js, no DOS emulator.
- Art is vector, drawn as code. Not pixel art, not original assets. View scales to device (no fixed 320x200 canvas).
- Cutscenes (item use, story) are in-engine animated vector scenes, not video files.
- Level logic is a task dependency web: each task has `requires` / `consumes` / `gives` over `item:*`, `flag:*`, `weapon:*` tokens (see `config/levels/mesto/tasks.json`). Items live in `config/items.json` (`src/game/items.ts`); item props name their item and `world.inventory` holds picked ones.

Code layout:

- `src/engine/` - game-agnostic core: fixed-step loop, input (bindings, buffer, record / replay), tiles and collision, view fit, rig tree, pose and draw. No React, Zustand, `game/` or `sandbox/` imports.
- `src/game/` - Colony 28 specifics: hero state machine (`hero/`), clip and movement config loaders, robot and gun models, sandbox level, scene and debug overlay renderers. `env/` ports the spike env primitives and assets to TypeScript (`paint.ts` primitives, `grime.ts` (`G`, port of spike `ENV.G`: `grain` speckle and mottle pattern fill, pooled `dirt`, rust `drips`, `rustPatch`, worn edge `chips`, `scorch` before and `rim` after a hole, `surface` and `wagon` combos; every mission 1 building, structure, machine and world prop wears it, items, people and the `crashedShip` stay clean), `assets.ts` registry by id, `props.ts`, `machines.ts`, `structures.ts`, `buildings.ts`, `guard.ts`; mission 2 assets of `spikes/shared/env-vesnice.js` in `vesnice.ts`, `vesniceProps.ts` and `bridgeGuard.ts`, the guard on the robot enemy rig with its own rifle model); the spikes stay the design source, so change an asset there first and re-port. `hero/look.ts` turns hero state into a pose: walk and run (and the blend into walking and running jumps) come from `hero/gait.ts`, a port of the spike gait engine checked against `gait.fixture.json` (regenerate from `spikes/movement/moves.js` in a browser when the spike gait changes); clips with `gait` in `config/hero/clips.json` have no pose keys. Every jump blends from its gait or its `base` pose into one leap pose in `blend`. Up held jumps again on every landing (`upHeld` in `hero/hero.ts`), so a held Up jumps on and on; only a press starts the first jump, so climbing off a ladder top with Up held does not jump. Death clips keep the lowest body point on the floor, carry the gun until their `dropped` gun key, then let go and slide it back; a `dust` event starts the landing dust. A dying hero explodes from the first death frame: `render/scene.ts` draws the enemy blast (`env/blast.ts`) over the collapse at the death clip time, and the `died` event cues the explosion sound (`stepWorld.ts`). The gun `shoot` clip stands on the `idle` legs, so no shooting robot splits its legs. Up while airborne (fall or jump) with the feet in a ladder column grabs the ladder, from any fall height and without fall damage. Ladder pose locks hands and feet on rungs from `hero.climb` (cells above the ladder bottom); the `ladder` env asset draws the rungs. No shadow while airborne; an enemy shadow draws only while the cell above its feet is in sight (`feetSeen` in `render/scene.ts`). A hidden hero (`hero.hidden`) is drawn before the enemies so they walk in front of it (`heroBehindEnemies`). `shots.ts` resolves every shot as instant hit-scan, nothing flies or is drawn: a hero `shot` casts a ray at the pose muzzle height from the hero centre up to `sightCells`, the fog edge or the first wall, and hits the first enemy or shootable prop on it with an impact spark (on a wall face when nothing is hit); a flyer is hit at any height above its floor (`shotBox`, spark on its hull); an enemy or guard shot adds to `world.heroHits`, which `updateHero` takes as hits unless the hero is hidden, dead or immortal; props block neither the hero nor shots. Each hero `shot` event spends one `hero.ammo` (start `ammo` in `config/hero/movement.json`, kept on respawn); at 0 the hero stops firing and cannot draw the gun. `hero.blaster` is the E-Blaster ammo (null until picked up, kept on respawn, `blaster` in `config/hero/movement.json`); key 3 arms it and `fireBeam` in `shots.ts` turns its `beam` events into `world.beam`, drawn by `render/scene.ts`; each tick hits every enemy whose shot box the beam line crosses between the hero body and the beam end, like gun shots, and an enemy that leaves the beam gets the hit reaction again when it comes back. An empty E-Blaster switches to the gun, an empty gun to the E-Blaster, both empty to fists. Only the held weapon is drawn. The sandbox `weapon` prop (`config/levels/sandbox.json`) is picked like an item, gives the E-Blaster and is drawn (`eBlaster` env asset) and pickable only while `hero.blaster` is null (`onGround` in `level/sandboxLevel.ts`). While hidden, arrows set `facing` without leaving cover; `hero/look.ts` turns the front-view `head` and `face` joints toward it. Shoot held on hide release starts the attack with the held weapon (gun or E-Blaster fire at once, fists punch). Weapon keys swap the weapon at once in any live state (`quickSwitch` in `hero/hero.ts`); only while hidden does the front-view `weaponSwitch` clip play, cut short by any other input. Run mode starts on and survives respawn. Enter rides the lift the hero stands fully on to its other stop (up unless at the top), also mid-walk or mid-run, unless an object to use is under him (`liftPress` in `hero/hero.ts`, `liftGoes` in `level/sandboxLevel.ts`); off the lift, Enter in the panel cell touching the shaft at a stop calls a resting lift to that stop, and does nothing while the lift stands there (`callFromPanel`); a locked lift says its hint and stays; Up and Down on a deck jump or duck. Every lift has two stops; jeskyne three-stop lifts are still to be split (`docs/requirements.md` Open). While a lift moves the hero cannot hide; he walks, runs, ducks and jumps on and off the deck freely, and a rising deck catches an airborne hero whose feet it passed this step (`risingDeck`), so no jump falls through it. `damage` in `hero/hero.ts` takes `energy.hit` off energy and starts `hitAge`; within `hitSlowMs` (600 ms, `config/hero/movement.json`) of the last hit a hero in run mode walks (and jumps a walking jump) instead of running, and a hit during a running jump drops it to walk speed, so it cannot outrun a burst; at 0 it spends a shield and refills to `energy.max`, or kills the hero when none is left (`config/hero/movement.json`). `level/enemy.ts` is the sandbox enemy: a `Hero` body that patrols its platform (turning at cells a prop blocks while they block, so no droid walks into the plasma barrier), stops and shoots a hero it sees (on its floor, or airborne up to `JUMP_REACH` (1.5) cells above it, so a jumping hero is seen like a walking one; walls and cells out of the hero's current sight block its sight), takes hero shots and punches (turning to the hero `reactMs` after the first hit), follows a hero it has seen (`tracking`): when that hero gets behind it, still in range and not hidden, it turns `reactMs` later; a hero that hides or leaves its floor or sight range is forgotten, (`landPunches` in `shots.ts`, `punch` in `config/hero/movement.json`), fires bursts (`burst`, then stands `pauseMs`, `config/levels/sandbox.json`; an enemy whose body box comes out of fog sight (`boxSeen`, `unseen`) first stands `reactMs` before; one already in sight fires at once, also at a hero that stops hiding) whose shots hit the hero it sees at once, explodes, leaves scrap and respawns. An enemy with `flight` (`config/levels/sandbox.json`) is a flyer: it patrols the air span of its floor at `speedScale` times the walk speed, cruises `hoverLift` cells up on a `wave`, dives at `climb` to `aimLift` (its gun at the standing hero gun) when it sees the hero, flies at the hero until `closeCells`, fires there; it dives only while it sees the hero; losing the hero before `aimLift` sends it back to its hover, once at `aimLift` or once hit it never climbs again (`flight.engaged`; a hit while cruising dives it to `aimLift`) and, like the droid, never turns to a hero behind it that it has not seen; `bodyBox` gives its hull box for hits; punches hit an enemy whose box overlaps the hero height (duck height for a duck punch), so a flyer takes them only once it dives; `env/flyer.ts` draws it in the flyer keys of `PALETTE` (grey hull, hump, window and lights like the grey droid, the old dark green top shell, red nose stripe only, original blue thruster; the acid guard head shares them) (port of the spike `flyer` ENV asset, explosion without wreck in `render/scene.ts`; its hit flash draws with a `shade`d palette, never `ctx.filter`, which costs Chrome about a second per frame on a software GPU). It is drawn with its own rigs (`createRigs(lod, true)`, the robot `enemy` variant) and `ENEMY_PALETTE` (greyscale, red visor) in `render/scene.ts`. `visibleEnemies` (`render/scene.ts`) skips pose and draw of enemies outside the view plus a margin. `render/environment.ts` draws the whole sandbox from env assets at game LOD: sky, backdrop scenery under a depth haze (`HAZE`), tiles, the rows under the world `ground` row (`world.json`, mesto 59, the street) under the darker `UNDERGROUND` shade, then dressing, so ceiling-mounted `stripLight` tubes stay bright, lifts, ladders and props, pickups (item, weapon) after every other prop so none hides behind one (props and lifts only when their art box meets the view; a prop without `anim` and not a guard draws from a sprite cached per asset, state, scale, lines and `size.top` (`putSprite`, `SPRITES_KEPT` 48), so its grime costs nothing per frame; lift shafts go into the cached `below` layer as `liftShaft`, only the `liftDeck` is drawn each frame, at its own origin shifted to the deck height, so its grime moves with it); `drawnTerrain` keeps terrain art off the world `bare` cell rects and off `=` lift stop cells, which draw as `liftLanding` (gameplay `world.terrain` is untouched); dressing never draws over a lift shaft, and the cells of each lift's bottom stop get a floor drawn behind the lift (`streetWalkway` on non-`=` cells, then the dressing clipped to those cells), so no pit shows under it, and the cells right under a bottom stop draw no ledge, so no second floor shows below the lift; a shaft row (not the bottom stop, no `=` cell) that a floor reaches from both sides, or from one side up to a wall on the other, gets that floor run on behind the lift (`behind` in `drawnTerrain`, `shaftFloor`): each half draws its neighbour run (walkway or girder) extended across and clipped to it, so the pattern continues, the dressing is painted there too (metro `tunnelFloor`), then `BEHIND_SHAFT` darkens it like a far limb; a `ceilingPipe` dressing (concrete pipe under a corridor ceiling, scenery `w` its length, elbow down at its left end; mesto runs one from the `waterPipe` to the `tapValveWheel`; `waterPipe` draws the concrete leg down from its elbow (`CEILING_PIPE.foot`), so the ceiling pipe `x` sits 3 units right of the water pipe cell left edge) draws its part inside a lift shaft the same way, darkened (`pipesBehind`); the static layers (below and above the hero) are cached per world and size in 512 device-px tiles (`render/tiles.ts`): tiles in the game window paint at once; the one-tile margin ring, nearest first, paints in a Worker (`render/tileWorker.ts` on `OffscreenCanvas`, started by `paintTilesAside` in `render/tilesAside.ts`, which rebuilds the world from `world.source`) and comes back as `ImageBitmap`s (`TileCache.adopt`); while a film plays, `askTiles` asks it for the tiles of the view the film returns to, so the first frame after it paints none; the cache key holds the scale as float32 (`Math.fround`), the value Chromium keeps in the context transform; without Worker or `OffscreenCanvas` the ring paints on the main thread, at least one tile per layer per frame and more while `PREFETCH_MS` (4 ms) of that layer's frame time lasts, none on a frame that painted a visible tile; offscreen canvases (tiles, sprites, grime grain) are `OffscreenCanvas`; each layer keeps its last 40 dropped tiles (`DROPPED_KEPT`) for a jump back and frees older ones, and never frees the tiles of its first view after start or a resize, so a respawn at spawn paints nothing; each tile paints only the terrain runs, ladders and scenery within one cell of it, indexed per cache tile (`bucketByTile`). Mission 1 adds the `tunnelGate` and `acidGuard` env assets; `env/guard.ts` ports the side acid guard of `spikes/shared/enemies.js` (state 0 alive, 1 wreck), which defines it as the spike `ENV` asset `acidGuard`. Every item in `config/items.json` names an env asset (the loader rejects one without), drawn on the ground and as its HUD icon. `pickup` in `hero/hero.ts` picks an item (or the weapon prop) on touch, after each hero step in any live state except hidden: its centre within `pickReach` (1 cell, `config/hero/movement.json`) of the hero centre, its floor at or under the feet and less than a hero height below; Enter uses an object only with the hero box over it; Down only ducks. A film start halts only a grounded hero (`stepWorld.ts`). Shared rect type: `src/game/geometry.ts`. `level/terrain.ts` classifies solid tiles into wall fills, `ledges` (touch a wall or solid tiles) and free-standing `girders`. `=` is a one-way floor (levels 2-4 floor tiles, `TileGrid.oneWay` with ladder tops): it holds the hero from above only, so he jumps up through it and walks under it, a lift carries him through it, it classifies and draws like a `#` floor run of that shape, blocks fog sight; shots and enemy sight pass it only where fog does not cover it, so with fog on they stop at the fog edge it makes. `config/levels/sandbox.json` holds the 48 x 32 map: `lifts` (each with optional `start` stop; walls and floors block it; a wall or floor cell the sight reaches from below stays covered, so a floor shows only from above or the side) ever covered stay uncovered (`revealed`); `seen` holds only the cells in the current sight, recomputed on a tick whose hero x, sight anchor, sight config or grid blocks (`TileGrid.version`) changed; the sight anchor eases (`followRate`) every tick to the hero floor: his y while standing or on a ladder, his takeoff floor (`fallFrom`) while airborne, so a held Up that jumps again on the landing step still moves it like walking, and his y once he leaves the sight rows; and every gameplay fog check (`seenAt`, `visible`, `fogEdge`) uses it, so remembered cells hide enemies and stop shots like fog; every hero shot ends without a spark `sightCells` from the hero or at the first covered cell; `render/fog.ts` draws covered cells at `opacity` and remembered ones at `rememberedOpacity` for the game window only (cell mask plus an 8 px per cell soft copy, `SOFT_CELL_PX`, never a whole-map canvas; a vertical cell edge where either cell is a wall or floor stays hard (`hardEdges`), so nothing on a floor above the sight shows through; both made once per fog, a fog version change repaints only the cells the sight left or entered plus `SOFT_BLUR_CELLS` around them; the window canvas carries a `WINDOW_MARGIN_PX` (128) margin, so a pan only copies a shifted part of it until the view leaves the margin; fog changes repaint only their cells, split into a left and right box; `glideOf` fades the two sight edge columns of each sight row by how much of each cell lies within `sightSpan` of the drawn hero x, render only) and the seen-cells clip (`seenPath`) that hides sparks and beam in fog; fog draws before the figures, and an enemy draws whole, over the fog, once any cell of its body box is seen (`boxSeen` in `level/enemy.ts`), else not at all. The hit effect is pose data: joint pose `tint` flashes the `chest` and `head` subtrees, plus a head snap and a star drawn by `render/scene.ts`.

## Spikes

Throwaway prototypes. They read `config/` through generated `spikes/shared/config.js` (`window.C28_CONFIG`); after editing `config/robots/*.json`, `config/cutscenes/*.json` or `config/levels/*/objects.json` run `node spikes/shared/build-config.mjs`. Every reference to the original game (images, file names, labels) goes through `spikes/shared/originals.js` (`ORIGINALS.on`, `src(path)`, `previewSheet`, `cutscenes`) or sits in an `<!-- originals -->` block; visible page text never names it, so the production build can drop it. No server needed: open in a browser via `file://` or with the VS Code "Live Preview" extension (`ms-vscode.live-server`). Plain HTML previews in VS Code webviews block the relative script and image loads.

- `spikes/shared/clock.js` - shared animation clock (`window.SPIKE_CLOCK`: `now()` ms, `seconds()`, `paused`). It adds a "Pause animations" checkbox to the page header (remembered in `localStorage`); every animated spike reads its time from it. Load it before the page scripts.
- `spikes/shared/xbot.js` - hero robot model (front, side, back) as a Canvas 2D part tree with named rig joints (`hip*`, `knee*`, `ankle*`, `arm*`, `fore*`, `body`, `head` and `chest` (side view), `head` and `face` (front view); back legs `leg*`, `thigh*`, `shin*`) and hand, back (side and back view) and foot (`heel*`, `toe*`; back view `foot*`) hooks. Front and back shoulder pads draw last and do not turn with the arm; both arms sit `shoulderIn` units in (`config/robots/xbot.json`), so the pads overlap the torso. `L` / `R` suffixes name the screen side, not the robot's side: front `armL` is the robot's right arm, back `armL` its left. A pose value is an angle or `{ rot, dx, dy, sx, sy, tint }` (`tint` shades that joint's subtree, e.g. `{ brightness, saturate }`). Hand hooks render before the hand parts, so a held prop sits inside the grip. `locate(root, hook, pose)` returns a hook's matrix; `solve(...)` fits two arm joints to a target (grid search over the joint ranges; the hand point comes from cached link matrices along the hook path, so it is fast; `src/game/robot/solve.test.ts` checks it against the plain tree walk). Parts shade with flat tone bands (cached `Path2D` per part and LOD, no gradients) and outline width follows the scale tracked down the tree. Builder options: `lod` (game LOD, use with `render(..., { simple: true })`), `farLimbs`, `badge` (side), `propBehindArm` (side, front), `rightArmFirst` (front), `leftArmBehind`, `rightForeBehind`, `thumbsBehind`, `forearmsUnder` (back), `enemy` (all views: no antennas, head crest, trefoil badge, horizontal leg stripes, shin slots or back panel lines; knees in leg armour). Classic script exposing `window.XBOT`, not an ES module, so pages work from `file://`.
- `spikes/shared/gun.js` - rotary gun model (`GUN.draw`, `GUN.hook` for hand and `back` hooks, `GUN.slung` draws it at the rest-pose back hook) and `GUN.holdPoses(side, front)` carry poses plus `FRONT_BARREL` (pass as `barrel` to `draw` / `hook`). Barrel keeps its true length unless the robot silhouette covers the muzzle in a view; then it stretches until the muzzle clears the silhouette by one barrel thickness. Needs `xbot.js` first.
- `spikes/robot-design/index.html` - design sheet rendering `xbot.js`, with palette editor, level guides, a game-size row of the simplified robot and original reference frames.
- `spikes/gun-design/index.html` - gun design sheet: side, held side and front, slung back, game size, original references.
- `spikes/enemy-design/index.html` - enemy design sheet with a Gun walker / Flyer / Acid guard / Shoot guard toggle (URL hash `#walker`, `#flyer`, `#guard`, `#shooter`). ## Research tools

`docs/research/tools/*.py` - Python decoders for original game data (numpy, Pillow). Positional CLI args, no `--help`.

- `fli.py` - Autodesk FLI decoder (all `.GRA` / `.ANM` files are FLI).
- `dumpframes.py <file.anm|gra> <outdir>` - dump frames as PNG + `.npy` plus `pal.npy`.
- `rendermap.py <Mxy.MAP> <frames dir> <out.png> [width] [scale] [frame offset] [index base]` - render a 160x80 map from dumped tileset frames.
- `tiles.py`, `stream.py`, `rewidth.py`, `width.py`, `localwidth.py` - inspect raw frame data at guessed widths.
- `pstrings.py <exe> [minlen]` - dump Pascal strings (cp852) from executables.

Binary and media research folders are local only (copyrighted, large); the list lives in `.gitignore`. A fresh clone lacks them, so spike reference panels stay empty. Original game files live in `docs/research/gamedata/raw/C28/`. `docs/research/video/` holds gameplay footage and picked reference frames (`frames-best/`, named by timestamp and content).
