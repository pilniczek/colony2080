## Commands

- `npm run dev` - Vite dev server, opens the home page (`index.html`: game name, mission select, dev links to the sandbox and every spike page) in browser. Agents start bare `npx vite --port 5199 --strictPort` (no browser); never pass `--open false`, Vite reads `false` as path `/false`.
- `npm run build` - production build of `index.html`, `sandbox.html` and `game.html` into `dist/` (`cheats.html` is dev only); `scripts/production.ts` (plugin in `vite.config.ts`) keeps the original game out of the published site: config JSON loses its citation and Czech-name text (`source`, `note`, `units`, `description`, `csName`, `cs`, `preview` blanked, `refs` emptied), `spikes/` is copied as a production variant (`<!-- originals -->` blocks cut, `shared/originals.js` switched off), `index.html` loses its `data-dev` elements (missions 2-4, the cheats link), and the build fails if any file in `dist/` still names the original game (`ORIGINAL_GAME` patterns). Code names (`xbot`, `C28_CONFIG`, `mesto`) may stay.
- `npm run preview` - production build, then serves `dist/` and opens the home page: the website as published (production spike variants without original game resources). Rerun after changes; it does not watch. Agents run `npx vite build && npx vite preview --port 5198 --strictPort`.
- `npm test` - Vitest (node environment) over `src/**/*.test.ts`.
- `npm run lint` - ESLint; `src/engine/**` may not import React, Zustand, `game/` or `sandbox/`.
- `npm run typecheck` - `tsc --noEmit`.
- `npm run test:visual` - Playwright runs `tools/visual/compare.html`: spike vs port robot trees and renders, hero and `enemy` variant, plus each env asset the sandbox uses (states, game LOD, ladder and sized variants) against its spike, and every cutscene at 9 times and 2 sizes, bare and filmed. `VISUAL_ONLY=id1,id2` runs only those cutscenes. The own-matrix render may differ by a few edge pixels because Chromium stores scale/translate DOMMatrix values as float32.

## Stack and architecture

Decided in `docs/requirements.md`:

- TypeScript + Vite. React only for the UI shell. Zustand bridges engine state to UI.
- Custom engine in plain TypeScript on Canvas 2D. Engine must not depend on React. No Next.js, no three.js, no DOS emulator.
- Art is vector, drawn as code. Not pixel art, not original assets. View scales to device (no fixed 320x200 canvas).
- Cutscenes (item use, story) are in-engine animated vector scenes, not video files.
- Level logic is a task dependency web: each task has `requires` / `consumes` / `gives` over `item:*`, `flag:*`, `weapon:*` tokens (see `config/levels/mesto/tasks.json`). Items live in `config/items.json` (`src/game/items.ts`); item props name their item and `world.inventory` holds picked ones.

Code layout:

- `src/engine/` - game-agnostic core: fixed-step loop, input (bindings, buffer, record / replay), tiles and collision, projectiles, view fit, rig tree, pose and draw. No React, Zustand, `game/` or `sandbox/` imports.
- `src/game/` - Colony 28 specifics: hero state machine (`hero/`), clip and movement config loaders, robot and gun models, sandbox level, scene and debug overlay renderers. `env/` ports the spike env primitives and assets to TypeScript (`paint.ts` primitives, `assets.ts` registry by id, `props.ts`, `machines.ts`, `structures.ts`, `buildings.ts`, `guard.ts`; mission 2 assets of `spikes/shared/env-vesnice.js` in `vesnice.ts`, `vesniceProps.ts` and `bridgeGuard.ts`, the guard on the robot enemy rig with its own rifle model); the spikes stay the design source, so change an asset there first and re-port. `hero/look.ts` turns hero state into a pose: walk and run (and the blend into walking and running jumps) come from `hero/gait.ts`, a port of the spike gait engine checked against `gait.fixture.json` (regenerate from `spikes/movement/moves.js` in a browser when the spike gait changes); clips with `gait` in `config/hero/clips.json` have no pose keys. Every jump blends from its gait or its `base` pose into one leap pose in `blend`. Death clips keep the lowest body point on the floor, carry the gun until their `dropped` gun key, then let go and slide it back; a `dust` event starts the landing dust. Up while airborne (fall or jump) with the feet in a ladder column grabs the ladder, from any fall height and without fall damage. Ladder pose locks hands and feet on rungs from `hero.climb` (cells above the ladder bottom); the `ladder` env asset draws the rungs. No shadow while airborne; an enemy shadow draws only while the cell above its feet is in sight (`feetSeen` in `render/scene.ts`). A hidden hero (`hero.hidden`) is drawn before the enemies so they walk in front of it (`heroBehindEnemies`). `shots.ts` turns `shot` events into hero bullets from the pose muzzle and stops them at walls with impact sparks; props block neither the hero nor bullets. Each hero `shot` event spends one `hero.ammo` (start `ammo` in `config/hero/movement.json`, kept on respawn); at 0 the hero stops firing and cannot draw the gun. `hero.blaster` is the E-Blaster ammo (null until picked up, kept on respawn, `blaster` in `config/hero/movement.json`); key 3 arms it and `fireBeam` in `shots.ts` turns its `beam` events into `world.beam`, drawn by `render/scene.ts`; each tick hits every enemy whose body box the beam line crosses between the hero body and the beam end, like bullets, and an enemy that leaves the beam gets the hit reaction again when it comes back. An empty E-Blaster switches to the gun, an empty gun to the E-Blaster, both empty to fists. Only the held weapon is drawn. The sandbox `weapon` prop (`config/levels/sandbox.json`) is picked like an item, gives the E-Blaster and is drawn (`eBlaster` env asset) and pickable only while `hero.blaster` is null (`onGround` in `level/sandboxLevel.ts`). While hidden, arrows set `facing` without leaving cover; `hero/look.ts` turns the front-view `head` and `face` joints toward it. Shoot held on hide release starts the attack with the held weapon (gun or E-Blaster fire at once, fists punch). Weapon keys swap the weapon at once in any live state (`quickSwitch` in `hero/hero.ts`); only while hidden does the front-view `weaponSwitch` clip play, cut short by any other input. Run mode starts on and survives respawn. Up and Down call the lift only with the hero fully on the deck and the lift able to go that way (`liftPress` in `hero/hero.ts`, `liftGoes` in `level/sandboxLevel.ts`); otherwise, and on a locked lift after its hint, they jump or duck. While a lift moves the hero cannot jump or hide, and `keepOnDeck` stops it at the deck edge. `damage` in `hero/hero.ts` takes `energy.hit` off energy and starts `hitAge`; within `hitSlowMs` (600 ms, `config/hero/movement.json`) of the last hit a hero in run mode walks (and jumps a walking jump) instead of running, so it cannot outrun a burst; at 0 it spends a shield and refills to `energy.max`, or kills the hero when none is left (`config/hero/movement.json`). `level/enemy.ts` is the sandbox enemy: a `Hero` body that patrols its platform, stops and shoots a hero it sees (walls and cells out of the hero's current sight block its sight), takes hero bullets and punches (turning to the hero `reactMs` after the first hit), follows a hero it has seen (`tracking`): when that hero gets behind it, still in range and not hidden, it turns `reactMs` later; a hero that hides or leaves its floor or sight range is forgotten, (`landPunches` in `shots.ts`, `punch` in `config/hero/movement.json`), fires bursts (`burst`, then stands `pauseMs`, `config/levels/sandbox.json`) with bullets that start at its body so a hero closer than its muzzle still gets hit, explodes, leaves scrap and respawns. An enemy with `flight` (`config/levels/sandbox.json`) is a flyer: it patrols the air span of its floor at `speedScale` times the walk speed, cruises `hoverLift` cells up on a `wave`, dives at `climb` to `aimLift` (its gun at the standing hero gun) when it sees the hero, flies at the hero until `closeCells`, fires there; it dives only while it sees the hero; losing the hero before `aimLift` sends it back to its hover, once at `aimLift` it never climbs again (`flight.engaged`) and, like the droid, never turns to a hero behind it that it has not seen; `bodyBox` gives its hull box for hits; punches hit an enemy whose box overlaps the hero height (duck height for a duck punch), so a flyer takes them only once it dives; `env/flyer.ts` draws it (port of the spike `flyer` ENV asset, explosion without wreck in `render/scene.ts`). It is drawn with its own rigs (`createRigs(lod, true)`, the robot `enemy` variant) and `ENEMY_PALETTE` (greyscale, red visor) in `render/scene.ts`. `visibleEnemies` (`render/scene.ts`) skips pose and draw of enemies outside the view plus a margin. `render/environment.ts` draws the whole sandbox from env assets at game LOD: sky, backdrop scenery under a depth haze (`HAZE`), tiles, lifts, ladders and props; `drawnTerrain` keeps terrain art off the world `bare` cell rects and off `=` lift stop cells, which draw as `liftLanding` (gameplay `world.terrain` is untouched); the static layers (below and above the hero) are cached per world and size in 512 device-px tiles (`render/tiles.ts`): tiles in the game window paint at once, the one-tile margin ring nearest first, at most one per layer per frame and none on a frame that painted a visible tile; each layer keeps its last 40 dropped tiles (`DROPPED_KEPT`) for a jump back and frees older ones, and never frees the tiles of its first view after start or a resize, so a respawn at spawn paints nothing; each tile paints only the terrain runs, ladders and scenery within one cell of it, indexed per cache tile (`bucketByTile`). Mission 1 adds the `tunnelGate` and `acidGuard` env assets; `env/guard.ts` ports the side acid guard of `spikes/shared/enemies.js` (state 0 alive, 1 wreck), which defines it as the spike `ENV` asset `acidGuard`. Every item in `config/items.json` names an env asset (the loader rejects one without), drawn on the ground and as its HUD icon. Down picks an item (or the weapon prop) whose centre is within `pickReach` (1 cell, `config/hero/movement.json`) of the hero centre; objects still need the hero box over them. Shared rect type: `src/game/geometry.ts`. `level/terrain.ts` classifies solid tiles into wall fills, `ledges` (touch a wall or solid tiles) and free-standing `girders`. `=` is a one-way floor (levels 2-4 floor tiles, `TileGrid.oneWay` with ladder tops): it holds the hero from above only, so he jumps up through it and walks under it, a lift carries him through it, it classifies and draws like a `#` floor run of that shape, blocks fog sight; bullets and enemy sight pass it only where fog does not cover it, so with fog on they stop at the fog edge it makes. `config/levels/sandbox.json` holds the 48 x 32 map: `lifts` (each with optional `start` stop; `liftAt` picks the one the hero stands on or whose shaft it is in; `reach.test.ts` checks that a lift's two stop floors connect only through it), `enemies` (`respawnMs: null` means no respawn), and `backdrop` / `dressing` scenery (tall non-blocking scenery stays in the backdrop). `resetWorld` restores lifts, props, enemies, bullets and fog when the hero dies. `fog.ts` is fog of war: cells the hero's sight (`rowsAbove` / `rowsBelow` in `config/camera.json`, `sightCells` each side from `config/hero/movement.json`; walls and floors block it) ever covered stay uncovered (`revealed`); `seen` holds only the cells in the current sight, recomputed each tick, and every gameplay fog check (`seenAt`, `visible`, `fogEdge`) uses it, so remembered cells hide enemies and stop shots like fog; every bullet vanishes without a spark `sightCells` from its shooter (`endX`); `shots.ts` drops bullets at the first covered cell without a spark; a bullet that crosses its range end or fog edge rests on that edge one step, so the hero hit check (run after `stepShots`) still catches a hero the shooter sees at the edge of its range, `render/fog.ts` draws covered cells at `opacity` and remembered ones at `rememberedOpacity` for the game window only (cell mask plus an 8 px per cell soft copy, `SOFT_CELL_PX`, never a whole-map canvas) and the seen-cells clip (`seenPath`) that hides the enemy, its bullets and sparks in fog. The hit effect is pose data: joint pose `tint` flashes the `chest` and `head` subtrees, plus a head snap and a star drawn by `render/scene.ts`.

- `src/game/level/mesto.ts` - `loadMesto` builds the mission 1 world through `loadSandbox` from `config/levels/mesto/` (`mestoJson`); `droidsOf` turns the 27 `chromeDroid` entries of `enemies.json` into non-respawning enemies with the sandbox enemy tuning; `flyersOf` does the same for the 17 `flyers` of `map.json` with the sandbox flyer `flight`. - `config/levels/<id>/map.json` - generated by `docs/research/tools/levelmap.py <level> <map> <layout> <enemies> <out>`, never hand-edit. Rows use `#` (solid wall or plank), `|` (invisible blocker, `TileGrid.solid` but not `wall`, so nothing is drawn), `=` (one-way floor, levels 2-4) and `.`. `lifts` have `top` and `bottom` and optional `stops` (else the lift stops at top and bottom), optional `enabledBy` (flag that powers the lift) and `hint` (subtitle while it is off). `taskWalls` are walls a task removes, not in `rows`; the converter's record, the game reads the gate cells from `world.json`. `droids` are the `chromeDroid` cells and patrols and `flyers` the flyer cells, patrols and plank row (`floor`, engine y + 6) from the research file `enemies.json` (4th converter arg), so the game never imports that file. `EXTRAS[1]["shaftFloors"]` in the script are `|` blockers under the two mesto bottom stops that stop a survivable drop past a lift; `plankGaps` keeps the crane mast gap (floor 10, cols 36-38) a plank without a wall and `holes` opens plank row 10 over the crane (cols 22-30), so the hero can drop past lift 14 to floor 16. Levels 2-4 add `enemies` (`kind`, `hp`, `cell`, `patrol`), `hazards` and `conveyors` (`level/hazards.ts`), `fallDeathCells`, `teleports` (`from`, pad `col` and `w`, `to`, optional `enabledBy` flag; Up with the hero standing on an enabled pad (foot row `from` row, centre column in the pad) moves him to stand on `to`, keeping facing, idle (`level/teleports.ts`, `padPress` in `hero/hero.ts`, after a lift deck and before a jump)) and `variants` (cell patches per later map state, their source maps in `variantSources`).
- `config/levels/mesto/world.json` - scenery and props. Prop `kind`: `item` (pick up), `object` (use), `gate` (no use, opened by `sets`; `solidStates` and `cells` make it block while in those states). `shootable` (`hits`, `state`, `gives`, `subtitle`) makes a prop take hero bullets and beams (`shots.ts`); `fires` (`facing`, `burst`, `pauseMs`, `states`) makes a prop fire droid bursts from its cannon at a hero it sees on its floor while in one of `states` (`level/guards.ts`: `ART` maps each guard asset to its muzzle, firing and explosion states; `fireGuards` in `shots.ts`), so the acid guard shoots until the acid wrecks it; a broken guard with an explosion state plays it for `BLAST.loop` (`brokenAge`) and leaves nothing (`env/blast.ts` holds the enemy blast shared by `render/scene.ts` and the `shootGuard` asset, `env/shootGuard.ts`); an item prop with `shownBy` (a flag) stays hidden and unpickable until that flag is set (`onGround`), so the ship part drops once the hull cover is shot off; `art` (cells) moves the art off the use x; `art.top` (cells above the art floor) passes `size.top` to the asset, so the crane chain runs up to the map top.
- `src/game/level/tasks.ts` - `runUse` runs the first open task of the used object whose `requires` hold: the shown item is the one picked last or chosen on the inventory screen, used items stay in the inventory unless the task `consumes` them (only the ship part trade does), `gives` adds items or flags, `sets` moves other props to a state, then `applyBlocks` rebuilds the prop blockers and the task subtitle shows. Each task runs once. A use with no match says a hint. `flag:levelComplete` ends the level. A task with `cutscene` (an id in `CUTSCENES`) starts `world.cutscene` from the use press instead of the use clip (`openTask` in `hero/hero.ts`); `stepCutscene` runs the task when the film ends.

- `src/game/level/reach.ts` - reach graph of the map (walk, jump, ladder, lift, enabled teleports) used by tests (`route.test.ts`, `reach.test.ts`) to check that tasks are reachable in order and lifts are not bypassed. `reach.test.ts` `GATED` lists per mission the cells reached only once a task gate opens (`byTask`) and cells never reached (`never`); every mission is checked with all task gates open.
- `src/game/level/hazards.ts` - `fallLimit` (world `fallDeathCells`: missing = hero config, `null` = no fall death; hero landing and reach `maxDrop` use it), `stepHazards` (a hazard hits when the hero centre column and foot cell `floor(y - 0.001)` are in its rect: `death` kills with reason `hazard`, `damage` drains `perSecond` energy through shields like `damage` without a hit flash and pushes `push` cells per s) and conveyors (a hero standing on a run cell, not on a lift, is moved `vx` cells per s through collision). `stepWorld` runs both after the hero; they act only on a live hero outside a film and not on enemies.
- `src/play/` - `game.html` entry: `main.tsx` calls `startRun` with `loadMission` of `missionFromQuery(location.search)`, saves (`mission` the mission id, `localStorage`), `MenuScreen.tsx` (pause menu and game over overlay from the store `menu` and `slots`), fog on, the sandbox HUD, the inventory screen (`src/sandbox/ui/InventoryScreen.tsx`; `I` opens it through `startRun`, which pauses the loop and takes the keys until it closes), `mapItem: mapItemOf(mission)` (the `M` map screen opens only with that item, else a hint), `Subtitle.tsx` (yellow caption at the bottom of the game window) and `LevelEnd.tsx` (keeps the final task subtitle with a link home once the level is complete). `originalOverlay.ts` loads only in dev (`import.meta.env.DEV`): key `o` toggles the original map of the mission over the level and `window.__teleport`, `__overlay`, `__fog`, `__pause`, `__flag(name)` (adds `flag:name`), `__give(item)`, `__kill()` and `__state()` (hero position and state, flags, shown item) are test helpers; the game loop runs only in a foreground tab.
- `src/sandbox/` - `sandbox.html` entry: `main.tsx` runs the loop, `store.ts` (Zustand) holds UI state and live tuning, `main.tsx` frames the game with `followView` (`src/engine/render/view.ts`): the hero stays in the view centre of `view` cells from `config/camera.json`, clamped at the map edges, and fog, overlays and the environment cache use the same transform. `ui/Hud.tsx` overlays the HUD frame (`dangerouslySetInnerHTML` of `hudSvg`, rebuilt only when life, reserve, shields, ammo, blaster ammo, weapon, run mode, shown item or size change) and `main.tsx` clips and fits the game to its window, `ui/` holds the React debug panel (time controls, overlays, record / replay, hero buttons, live ammo, blaster ammo (above 0 gives the E-Blaster) and shields (inputs clamped to their range), tuning with JSON export for `config/hero/`, Films: pick any film and play it now, the hero halts as under any film). The sandbox crowbar, crane key and E-Blaster pickups play their mission 1 pickup films. The engine pushes into the store once per rendered frame and reads tuning from it each step.

Build order: movement overview page, engine core and movement sandbox, cutscene framework, Colony 28 clone systems, then mission 1 (`mesto`).

## Spikes

Throwaway prototypes. They read `config/` through generated `spikes/shared/config.js` (`window.C28_CONFIG`); after editing `config/robots/*.json`, `config/cutscenes/*.json` or `config/levels/*/objects.json` run `node spikes/shared/build-config.mjs`. Every reference to the original game (images, file names, labels) goes through `spikes/shared/originals.js` (`ORIGINALS.on`, `src(path)`, `previewSheet`, `cutscenes`) or sits in an `<!-- originals -->` block; visible page text never names it, so the production build can drop it. No server needed: open in a browser via `file://` or with the VS Code "Live Preview" extension (`ms-vscode.live-server`). Plain HTML previews in VS Code webviews block the relative script and image loads.

- `spikes/shared/clock.js` - shared animation clock (`window.SPIKE_CLOCK`: `now()` ms, `seconds()`, `paused`). It adds a "Pause animations" checkbox to the page header (remembered in `localStorage`); every animated spike reads its time from it. Load it before the page scripts.
- `spikes/shared/xbot.js` - hero robot model (front, side, back) as a Canvas 2D part tree with named rig joints (`hip*`, `knee*`, `ankle*`, `arm*`, `fore*`, `body`, `head` and `chest` (side view), `head` and `face` (front view); back legs `leg*`, `thigh*`, `shin*`) and hand, back (side and back view) and foot (`heel*`, `toe*`; back view `foot*`) hooks. Front and back shoulder pads draw last and do not turn with the arm; both arms sit `shoulderIn` units in (`config/robots/xbot.json`), so the pads overlap the torso. `L` / `R` suffixes name the screen side, not the robot's side: front `armL` is the robot's right arm, back `armL` its left. A pose value is an angle or `{ rot, dx, dy, sx, sy, tint }` (`tint` shades that joint's subtree, e.g. `{ brightness, saturate }`). Hand hooks render before the hand parts, so a held prop sits inside the grip. `locate(root, hook, pose)` returns a hook's matrix; `solve(...)` fits two arm joints to a target (grid search over the joint ranges; the hand point comes from cached link matrices along the hook path, so it is fast; `src/game/robot/solve.test.ts` checks it against the plain tree walk). Parts shade with flat tone bands (cached `Path2D` per part and LOD, no gradients) and outline width follows the scale tracked down the tree. Builder options: `lod` (game LOD, use with `render(..., { simple: true })`), `farLimbs`, `badge` (side), `propBehindArm` (side, front), `rightArmFirst` (front), `leftArmBehind`, `rightForeBehind`, `thumbsBehind`, `forearmsUnder` (back), `enemy` (all views: no antennas, head crest, trefoil badge, horizontal leg stripes, shin slots or back panel lines; knees in leg armour). Classic script exposing `window.XBOT`, not an ES module, so pages work from `file://`.
- `spikes/shared/gun.js` - rotary gun model (`GUN.draw`, `GUN.hook` for hand and `back` hooks, `GUN.slung` draws it at the rest-pose back hook) and `GUN.holdPoses(side, front)` carry poses plus `FRONT_BARREL` (pass as `barrel` to `draw` / `hook`). Barrel keeps its true length unless the robot silhouette covers the muzzle in a view; then it stretches until the muzzle clears the silhouette by one barrel thickness. Needs `xbot.js` first.
- `spikes/robot-design/index.html` - design sheet rendering `xbot.js`, with palette editor, level guides, a game-size row of the simplified robot and original reference frames.
- `spikes/gun-design/index.html` - gun design sheet: side, held side and front, slung back, game size, original references.
- `spikes/enemy-design/index.html` - enemy design sheet with a Gun walker / Flyer / Acid guard / Shoot guard toggle (URL hash `#walker`, `#flyer`, `#guard`, `#shooter`). Gun walker: hero rig built with `enemy: true`, recoloured by `XBOT.shade` keeping the red visor (brightness, saturation sliders). Every kind has per-colour overrides with JSON export, full and game size, a hero for scale and original references; acid guard views show level guides (`ENEMIES.GUARD_LEVELS`: top, visor, hip, knee, foot).
- `spikes/shared/enemies.js` - flyer and acid guard models (`window.ENEMIES`) on `env.js` primitives, units are original pixels; drawn with `ENV.draw` and scaled to the robot by hero height (1.9 cells). `FLYER` (states hover, firing, explode; nose right) carries a side-mounted variant of the `gun.js` rotary gun and leaves no wreck. `blast` and `scrap` copy the game enemy blast and scrap pile from `src/game/render/scene.ts` (units: hero height = 147); the gun walker shows them as its explosion and wreck views. `GUARD` is the side view, a compact BattleTech-style walker (states idle, firing, acid, wreck; faces left), `GUARD_FRONT` the front view with the same parts (idle, firing); both draw at `GUARD_SIZE`. `TROOPER` is the shoot guard (states idle, firing, explode; faces right): a crouched Terminator, Alien and dinosaur mashup, no bones: a level capsule head (`DOME`: straight top flush with the forehead, rounded back, two grooves, one rivet centred in each section), a humanoid face with a slim red visor and a small sharp-cornered jaw, short fat back pipes over the shell with rounded lower ends, a rounded pelvis with round hip joints, the acid guard leg armour on humanoid forward knees (`sideLegArmor` options `forward`, `pad`, `trim`, `padAt`: larger raised knee pads) posed like the original (front leg crouched, rear leg braced back), and a tail that drops then trails; every trim line shares the muted `trim` colour and one width (`TROOPER_TRIM`) and spans its part (shoulder dome middle, pelvis, thighs, shins, knee pads) whose arm is the `xbot.js` enemy side arm at 1.35x in the guard gunmetal holding its rifle in the carry pose; `TROOPER_MUZZLE` comes from that pose. Spike `ENV` assets `acidGuard` (alive, wreck, firing) and `shootGuard` mirror them for the port. Needs `xbot.js`, `gun.js` and `env.js` first.
- `spikes/shared/env.js` - environment asset registry and Canvas 2D primitives (`window.ENV`: `define`, `draw`, `PALETTE` with 4-tone materials (`olive`, `denim`, `jacket`, `skin`, `hair`, `boot` among them), `P.box` / `poly` / `cylV` / `mesh` / `truss` / `hazard` (colour options) / `slab` (thin-edge fill for big surfaces) / `shape` / `line` / `curve` / `beam` ...). Units are original pixels (1 tile = 24, floor at y 0, up is negative). An asset is `{ id, box, anim, draw(ctx, state, t) }`; `state` indexes the object's `states` in `config/levels/mesto/objects.json`. `size` option on `ENV.draw` (`w`, `h`, `top`, `py`, `rung`) draws an asset at another width or height, defaults keep the sheet output; `ladder` is a non-interactive structure asset (`rung` spacing matches `RUNG`). Mission 1 assets live in `env-props.js`, `env-machines.js`, `env-structures.js`, `env-buildings.js` (the object's `sheet`); missions 2-4 own assets in `env-vesnice.js`, `env-jungle.js`, `env-jeskyne.js`.
- `spikes/env-design/index.html` - environment sheet: mission select (`?mission=`) over every `config/levels/*/objects.json`, assets filter (`?scope=`: all, shared with another mission by object id, this mission only), every object of the mission (interactive first), our vector variant per state, original crops under it, hero for scale, game LOD and tile grid toggles.
- `spikes/items-design/index.html` - item sheet: each `config/items.json` item with its original inventory preview spinning (cropped from `docs/research/gamedata/png/PR*_sheet.png`, local only), our env asset, HUD icon, game LOD and other states.
- `spikes/hud-design/index.html` - HUD frame design sheet (inline SVG built from strings): aspect, weapon, bonus, ammo, life, run, shields and item controls, side by side with original screenshots, and the inventory screen below it (held items and cursor controls). Gun and fist icons render from `gun.js` and `xbot.js` to canvas images. Same layout as `src/game/hud/`; change both together.
- `spikes/movement/movement.html`, `interaction.html`, `fight.html` - movement overview by category, sharing `moves.js` and `style.css`: one non-interactive cell per move looping forever (cutscene cells add a progress bar and loop time), game-LOD robot, Fists / Gun / Blaster switch at the top (Blaster: the hero holds the E-Blaster and the shooting cells fire its beam). An interaction can trigger a cutscene (`triggering` in `moves.js`; `interaction.html` has a cell per mission 1 film, `FILMS`: the use, pickup or approach in front of the object's env asset, then the film): the cell plays the interaction in front of the cutscene backdrop (`backdrop(ctx, x, floorY, scale, t)`, same world at robot scale), then the cutscene. Click such a cell to open the cutscene player (`player.js`, `interaction.html` only): scrubber, speed, loop, side-by-side original frames, palette editor with JSON export.
- `spikes/shared/cutscenes.js` - vector cutscenes (`window.CUTSCENES`), each `{ name, duration, palette, backdrop, render(ctx, w, h, t), ref }`. `crowbarDoor` (crowbar opens train door, agreed version) uses `xbot.js` with a two-handed grip. Tracks, clip window (`clip.start..clip.end` on the original `METROPAC.ANM` timeline), robot x (same in both shots), crowbar size (same in both views) and pry swing (`pullArmDeg` / `pullForeDeg`) come from `config/cutscenes/crowbar-door.json`; stance is the `moves.js` `STAND` pose; `ref` maps time to original `METROPAC.ANM` frames in `docs/research/gamedata/png/METROPAC/`. Played by the `Use crowbar` cell in `spikes/movement/interaction.html`. `CUTSCENES.securityCam(ctx, w, h, t, label)` draws the security camera look (grain tiles, scanlines, vignette, dead pixels, corner brackets, label, REC dot, timestamp) over a frame; the player and the crowbar cell use it; `src/game/cutscene/securityCam.ts` ports it. `CUTSCENES.kit` (`sample`, `ease`, `filmRef`, `placeholder`, `FILM`, shapes, stage fit, camera, outline width, seeded random, robot placement, the closed-form arm `reach`, and the speed helpers `stillLayer` (a layer cached per canvas size, transform and key once it repeats), `rowFill` (a full-width vertical gradient stretched from a one-pixel strip), `sheetDraw` / `sheetBlit`; ported in `src/game/cutscene/kit.ts`) serves the per-film scripts in `spikes/shared/cutscenes/<kebab>.js` (each sets `window.CUTSCENES.<id>`; pages load them alphabetically, so a later file may reuse an earlier one's helpers). `ORIGINALS.cutscenes.<id>` maps film time to the original clip frames, per shot when the clips carry start times.

## Research tools

`docs/research/tools/*.py` - Python decoders for original game data (numpy, Pillow). Positional CLI args, no `--help`.

- `fli.py` - Autodesk FLI decoder (all `.GRA` / `.ANM` files are FLI).
- `dumpframes.py <file.anm|gra> <outdir>` - dump frames as PNG + `.npy` plus `pal.npy`.
- `rendermap.py <Mxy.MAP> <frames dir> <out.png> [width] [scale] [frame offset] [index base]` - render a 160x80 map from dumped tileset frames.
- `tiles.py`, `stream.py`, `rewidth.py`, `width.py`, `localwidth.py` - inspect raw frame data at guessed widths.
- `pstrings.py <exe> [minlen]` - dump Pascal strings (cp852) from executables.

Binary and media research folders are local only (copyrighted, large); the list lives in `.gitignore`. A fresh clone lacks them, so spike reference panels stay empty. Original game files live in `docs/research/gamedata/raw/C28/`. `docs/research/video/` holds gameplay footage and picked reference frames (`frames-best/`, named by timestamp and content).
