## Reporting work

Every final report that adds, changes or finds something visible in a mission map gives one `moveto(x,y)` per spot (world.json coords, y the floor row), on a cell the hero can stand on next to the spot, so the user can check it in game. More than 3 spots: also give every `moveto` on one line, separated by spaces, ready to paste into the debug panel Tour box. Changes with no map spot (films, HUD, code only) say how to see them instead (e.g. debug panel Films).

## Commands

- `npm run dev` - Vite dev server, opens the home page (`index.html`: game name, mission select, dev links to the sandbox and every spike page) in browser. Agents start bare `npx vite --port 5199 --strictPort` (no browser); never pass `--open false`, Vite reads `false` as path `/false`.
- `npm run build` - production build of `index.html`, `sandbox.html` and `game.html` into `dist/` (`cheats.html` is dev only); `scripts/production.ts` (plugin in `vite.config.ts`) keeps the original game out of the published site: config JSON (page and Worker bundles, `scrub` plugin and `worker.plugins`) loses its citation and Czech-name text (`source`, `note`, `units`, `description`, `csName`, `cs`, `preview` blanked, except `cs` in `config/items.json`, the Czech item names the game shows (`scrubConfigFile`), `refs` emptied), `spikes/` is copied as a production variant (`<!-- originals -->` blocks cut, `shared/originals.js` switched off), `index.html` loses its `data-dev` elements (missions 2-4, the cheats link), and the build fails if any file in `dist/` still names the original game (`ORIGINAL_GAME` patterns). Code names (`xbot`, `C28_CONFIG`, `mesto`) may stay.
- `npm run preview` - production build, then serves `dist/` and opens the home page: the website as published (production spike variants without original game resources). Rerun after changes; it does not watch. Agents run `npx vite build && npx vite preview --port 5198 --strictPort`.
- `npm run dev:debug` / `npm run preview:debug` - same with Vite mode `debugging`: `.env.debugging` sets `VITE_START_CHEAT=c2080isdebugging`, which `startRun` enters at start (any cheat code works there).
- `npm test` - Vitest (node environment) over `src/**/*.test.ts`.
- `npm run lint` - ESLint; `src/engine/**` may not import React, Zustand, `game/` or `sandbox/`.
- `npm run typecheck` - `tsc --noEmit`.
- `npm run test:visual` - Playwright runs `tools/visual/compare.html`: spike vs port robot trees and renders, hero and `enemy` variant, plus each env asset the sandbox uses (states, game LOD, ladder and sized variants) against its spike, and every cutscene at 9 times and 2 sizes, bare and filmed. `VISUAL_ONLY=id1,id2` runs only those cutscenes. The own-matrix render may differ by a few edge pixels because Chromium stores scale/translate DOMMatrix values as float32.
- `npm run sound:compare [id ...]` - renders each sound recipe and scores it against its original sound (sample ratio, envelope correlation, spectrogram distance, level); `tools/sound/compare.ts` holds `ORIGINAL_OF`, the id to original file map, and writes spectrogram PNG pairs to the OS temp dir (`c2080-sound/sound`). Needs the local research files.
- `node tools/map/crop.mjs <map png> <col> <row> <cols> <rows> <out.png> [scale]` - crops a decoded original map (`docs/research/gamedata/png/maps/`, local only, 24 px per cell) at those cells with a yellow cell grid and col / row labels every 5 cells, for step 2 of `docs/blueprints/map-composition.md`; `scale` (default 2) enlarges it. Runs the Playwright default Chromium.

## Stack and architecture

Decided in `docs/requirements.md`:

- TypeScript + Vite. React only for the UI shell. Zustand bridges engine state to UI.
- Custom engine in plain TypeScript on Canvas 2D. Engine must not depend on React. No Next.js, no three.js, no DOS emulator.
- Art is vector, drawn as code. Not pixel art, not original assets. View scales to device (no fixed 320x200 canvas).
- Cutscenes (item use, story) are in-engine animated vector scenes, not video files.
- Level logic is a task dependency web: each task has `requires` / `consumes` / `gives` over `item:*`, `flag:*`, `weapon:*` tokens (see `config/levels/mesto/tasks.json`). Items live in `config/items.json` (`src/game/items.ts`); item props name their item and `world.inventory` holds picked ones.

Code layout:

- `src/engine/` - game-agnostic core: fixed-step loop, input (bindings, buffer, record / replay), tiles and collision, view fit, rig tree, pose and draw. No React, Zustand, `game/` or `sandbox/` imports.
- `src/game/` - Colony 28 specifics: hero state machine (`hero/`), clip and movement config loaders, robot and gun models, sandbox level, scene and debug overlay renderers. `env/` ports the spike env primitives and assets to TypeScript (`paint.ts` primitives, `grime.ts` (`G`, port of spike `ENV.G`: `grain` speckle and mottle pattern fill, pooled `dirt`, rust `drips`, `rustPatch`, worn edge `chips`, `scorch` before and `rim` after a hole, `surface` and `wagon` combos, `inside` clips grime to a surface region minus its dark openings (`rectsRegion`, `polysRegion`, `rectPts`), so no grime hangs in the air or covers a window, door, vent or hole; every mission 1 building, structure, machine and world prop wears it, items, people and the `crashedShip` stay clean), `assets.ts` registry by id, `props.ts`, `machines.ts`, `structures.ts`, `buildings.ts`, `guard.ts`; missions 2-4 interactive object, hazard and item assets of `spikes/shared/env-vesnice.js`, `env-jungle.js` and `env-jeskyne.js` in `vesnice.ts` (shared helpers) with `vesniceProps.ts` and `radioGuard.ts` (the walkie-talkie guard on the robot enemy rig with its own rifle model), `jungle.ts` and `jeskyne.ts`, each id list (`VESNICE_IDS`, `JUNGLE_IDS`, `JESKYNE_IDS`) added by `assets.ts` to `BASE_IDS`; no scenery, terrain or sky asset of missions 2-4 until their design step); the spikes stay the design source, so change an asset there first and re-port. `hero/look.ts` turns hero state into a pose: walk and run (and the blend into walking and running jumps) come from `hero/gait.ts`, a port of the spike gait engine checked against `gait.fixture.json` (regenerate from `spikes/shared/gait.js` when the spike gait changes); clips with `gait` in `config/hero/clips.json` have no pose keys. Up held jumps again on every landing (`upHeld` in `hero/hero.ts`), so a held Up jumps on and on; only a press starts the first jump, so climbing off a ladder top with Up held does not jump. Death clips keep the lowest body point on the floor, carry the gun until their `dropped` gun key, then let go and slide it back; a `dust` event starts the landing dust. A dying hero explodes from the first death frame: `render/scene.ts` draws the enemy blast (`env/blast.ts`) over the collapse at the death clip time, and the `died` event cues the explosion sound (`stepWorld.ts`). The gun `shoot` clip stands on the `idle` legs, so no shooting robot splits its legs. Ladder pose locks hands and feet on rungs from `hero.climb` (cells above the ladder bottom); the `ladder` env asset draws the rungs. No shadow while airborne; an enemy shadow draws only while the cell above its feet is in sight (`feetSeen` in `render/scene.ts`). A hidden hero (`hero.hidden`) is drawn before the enemies so they walk in front of it (`heroBehindEnemies`). `shots.ts` resolves every shot except enemy rockets and missiles as instant hit-scan, nothing flies or is drawn: a hero `shot` casts a ray at the pose muzzle height from the hero centre up to `sightCells`, the fog edge or the first wall, and hits the first enemy or shootable prop on it with an impact spark (on a wall face when nothing is hit); a flyer is hit at any height above its floor (`shotBox`, spark on its hull); an enemy or guard shot adds to `world.heroHits`, which `updateHero` takes as hits unless the hero is hidden, dead or immortal; props block neither the hero nor shots. Run mode starts on and survives respawn. - `spikes/env-design/index.html` - environment sheet: mission select (`?mission=`) over every `config/levels/*/objects.json`, every object of the mission (interactive, then non-interactive original, then non-interactive new: objects with `"origin": "new"` in `objects.json`, assets we invented; objects with the same `family` share one section, states side by side), our vector variant per state, original crops under it, hero for scale (game height, 1.9 cells = 45.6 units) and tile grid always on, `Video LOD` checkbox (off: every view at game LOD, on: full detail for in-game videos).
- `spikes/items-design/index.html` - item sheet: each `config/items.json` item with its original inventory preview spinning (cropped from `docs/research/gamedata/png/PR*_sheet.png`, local only), our env asset, HUD icon, game LOD and other states.
- `spikes/hud-design/index.html` - HUD frame design sheet (inline SVG built from strings): aspect, weapon, bonus, ammo, life, run, shields and item controls, side by side with original screenshots, and the inventory screen below it (held items and cursor controls). Gun and fist icons render from `gun.js` and `xbot.js` to canvas images. Same layout as `src/game/hud/`; change both together.
- `spikes/movement/movement.html`, `interaction.html`, `fight.html` - movement overview by category, sharing `moves.js` and `style.css`: one non-interactive cell per move looping forever (cutscene cells add a progress bar and loop time), game-LOD robot, Fists / Gun / Blaster switch at the top (Blaster: the hero holds the E-Blaster and the shooting cells fire its beam). An interaction can trigger a cutscene (`triggering` in `moves.js`; `interaction.html` has a cell per mission 1 film, `FILMS`: the use, pickup or approach in front of the object's env asset, then the film): the cell plays the interaction in front of the cutscene backdrop (`backdrop(ctx, x, floorY, scale, t)`, same world at robot scale), then the cutscene. Click such a cell to open the cutscene player (`player.js`, `interaction.html` only): scrubber, speed, loop, side-by-side original frames, palette editor with JSON export.
- `spikes/shared/cutscenes.js` - vector cutscenes (`window.CUTSCENES`), each `{ name, duration, palette, backdrop, render(ctx, w, h, t), ref }`. `crowbarDoor` (crowbar opens train door, agreed version) uses `xbot.js` with a two-handed grip. Tracks, clip window (`clip.start..clip.end` on the original `METROPAC.ANM` timeline), robot x (same in both shots), crowbar size (same in both views) and pry swing (`pullArmDeg` / `pullForeDeg`) come from `config/cutscenes/crowbar-door.json`; stance is the `moves.js` `STAND` pose; `ref` maps time to original `METROPAC.ANM` frames in `docs/research/gamedata/png/METROPAC/`. Played by the `Use crowbar` cell in `spikes/movement/interaction.html`. `CUTSCENES.securityCam(ctx, w, h, t, label)` draws the security camera look (grain tiles, scanlines, vignette, dead pixels, corner brackets, label, REC dot, timestamp) over a frame; the player and the crowbar cell use it; `src/game/cutscene/securityCam.ts` ports it. `CUTSCENES.kit` (`sample`, `ease`, `filmRef`, `placeholder`, `FILM`, shapes, stage fit, camera, outline width, seeded random, robot placement, the closed-form arm `reach`, and the speed helpers `stillLayer` (a layer cached per canvas size, transform and key once it repeats), `rowFill` (a full-width vertical gradient stretched from a one-pixel strip), `sheetDraw` / `sheetBlit`; ported in `src/game/cutscene/kit.ts`) serves the per-film scripts in `spikes/shared/cutscenes/<kebab>.js` (each sets `window.CUTSCENES.<id>`; pages load them alphabetically, so a later file may reuse an earlier one's helpers). `ORIGINALS.cutscenes.<id>` maps film time to the original clip frames, per shot when the clips carry start times.
- `spikes/shared/robot-view.js` - robot vision look (`ROBOT_VIEW.draw(ctx, w, h, t)`; its target reticle has no match label or bar), ported by `src/game/cutscene/robotView.ts`. `spikes/shared/film-look.js` (`FILM_LOOK.overlay(ctx, w, h, t, scene)`) picks it or the security camera per shot from the config `views`; the player, the interaction cells and the cutscene sheet use it. Both looks sit side by side in the HUD design sheet's Film looks section.
- `spikes/cutscene-design/index.html` - cutscene sheet: every mission 1 film looping in play order, click opens the player (scrubber, speed, palette, original frames).
- `spikes/sound-design/index.html` - sound sheet: every `SOUNDS` recipe with play, rate (default: its main in-game rate, film-only sounds their most common film rate) and vol, waveform and spectrogram; the `<!-- originals -->` block holds the id to original file map and adds the original's play button, waveform and spectrogram (served pages only, `file://` blocks the fetch). It reads `spikes/shared/sounds.js` (`window.C28_SOUNDS = { SOUNDS, BASE_RATE }`), a rolldown bundle of the recipes; after changing a recipe run `node spikes/shared/build-sounds.mjs`.

## Research tools

`docs/research/tools/*.py` - Python decoders for original game data (numpy, Pillow). Positional CLI args, no `--help`.

- `fli.py` - Autodesk FLI decoder (all `.GRA` / `.ANM` files are FLI).
- `dumpframes.py <file.anm|gra> <outdir>` - dump frames as PNG + `.npy` plus `pal.npy`.
- `rendermap.py <Mxy.MAP> <frames dir> <out.png> [width] [scale] [frame offset] [index base]` - render a 160x80 map from dumped tileset frames.
- `tiles.py`, `stream.py`, `rewidth.py`, `width.py`, `localwidth.py` - inspect raw frame data at guessed widths.
- `pstrings.py <exe> [minlen]` - dump Pascal strings (cp852) from executables.

Binary and media research folders are local only (copyrighted, large); the list lives in `.gitignore`. A fresh clone lacks them, so spike reference panels stay empty. Original game files live in `docs/research/gamedata/raw/C28/`. `docs/research/video/` holds gameplay footage and picked reference frames (`frames-best/`, named by timestamp and content).
