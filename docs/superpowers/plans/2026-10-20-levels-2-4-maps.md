# Levels 2-4 maps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Missions 2-4 (`vesnice`, `jungle`, `jeskyne`) load in `game.html` as walkable maps with lifts, enemies, hazards and conveyors, built by one converter from decoded data.

**Architecture:** `docs/research/tools/levelmap.py` replaces `mestomap.py` and writes `config/levels/<id>/map.json` for all four missions. `src/game/level/missions.ts` turns any `map.json` into `SandboxJson` (generalising `mestoJson`). The world gains `fallDeathCells`, `hazards`, `conveyors` and `teleports`; reach tests run on every mission.

**Tech Stack:** Python 3 (numpy) for the converter, TypeScript + Vitest for the game.

**Spec:** `docs/superpowers/specs/2026-10-20-levels-2-4-maps-design.md`

## Global Constraints

- Map frame: map column = engine x + 6, plank row = engine y + 6, stand row = engine y + 5. Map 160 x 80 cells.
- Row chars: `#` solid and drawn, `|` solid and invisible, `.` open (`config/levels/mesto/map.json` schema).
- `config/levels/*/map.json` is generated, never hand-edited.
- Level 1 output of `levelmap.py` equals today's `config/levels/mesto/map.json` byte for byte.
- `fallDeathCells` in `map.json`: missing = hero config value (7), `null` = no fall death.
- Engine (`src/engine/**`) gets no game imports; all new logic lives in `src/game/`.
- No code comments, no em dash, docs in caveman lite.
- Production build must stay free of original-game names (`scripts/production.ts`); `map.json` `source` strings are blanked there.

## Review Focus

- A spawn cell over open air: the converter drops it to the first floor below; `missions.test.ts` checks every spawn stands on a solid cell.
- An enemy cell or patrol end over open air or inside a wall: `missions.test.ts` checks each enemy foot cell is open with a solid cell below.
- Lava band covering a lift stop or the spawn: `missions.test.ts` checks no `death` hazard overlaps the spawn or any lift stop cell.
- A conveyor pushing the hero into a wall: conveyor motion goes through the normal collision move, tested in `conveyor.test.ts`.
- Save from mission 2 loaded in mission 1: `checkSnapshot` already returns `misfit` on prop, lift and enemy counts; `missions.test.ts` adds a cross-mission snapshot case.
